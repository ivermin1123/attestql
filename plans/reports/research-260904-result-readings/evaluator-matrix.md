# Evaluator comparison matrix (supplement to research-260904-result-readings.md)

One row per public evaluator's own result-comparison function, read at the pinned commit in
`sources.json`. `db_id` and mechanism names use the terms already fixed by the tool: multiset
means row multiplicity kept, set means multiplicity dropped, `R-ORD`/`R-SET` are the tool's own
labels for reference.

| # | Evaluator (function \@ commit) | Grain | Row order | Where compared | Columns | Float | NULL | Type coercion | Timeout / error | DISTINCT | Other |
|---|---|---|---|---|---|---|---|---|---|---|---|
| a1 | BIRD Mini-Dev `calculate_ex`\@b3d4bcbb[^a] | set, drops multiplicity | never | Python, `cursor.fetchall()` tuples via `set()` | position only, no name/count check beyond tuple length inside `set` | Python `==`/hash, no tolerance | a row holding `None` compares like any value | `1==1.0==True` collapse (Python hash identity) | timeout and any exception both score 0, same as a wrong answer | never stripped or added | PostgreSQL/MySQL/SQLite branches share one `execute_sql`; no ORDER BY awareness at all |
| a2 | original BIRD `execute_sql`\@483554ea[^a] | set | never | same as a1 | same | same | same | same | same | never | SQLite only, no dialect branch |
| a3 | BIRD VES `iterated_execute_sql`\@483554ea[^a] | set (gates on a1's check) | never | same | n/a | n/a | n/a | same | a failed gate scores 0 efficiency | never | one sentence: only correct-by-a1 pairs get timed, an efficiency ratio (predicted vs gold latency, 3-sigma-clipped) is the score, not a second result reading |
| b1 | Spider 1.0 exact match, `Evaluator`/`eval_sel` etc.\@b7b5b8c8[^b] | n/a: compares SQL AST components (SELECT/WHERE/GROUP/ORDER/nesting), not results | n/a | Python, on parsed clause lists, partial-credit F1 per component | column identity by AST `val_unit`, not execution | n/a | n/a | n/a | a query that fails to parse is a hard 0 for that component | n/a | never sees the database; cannot judge two different statements that answer the same question differently in structure but agree in results |
| b2 | Spider 1.0 execution accuracy `eval_exec_match`\@b7b5b8c8[^b] | list per selected column (dict of lists), so order-sensitive by construction | always matters (positional list equality inside the dict) | Python, SQLite `fetchall()`, columns mapped by AST `val_unit`/foreign-key identity, not position | matched by semantic column identity from the parsed SELECT list and a foreign-key map, not by declared type; a prediction naming an extra/fewer column breaks the map | Python `==` | untreated | same as a1 | a failed `p_str` execution scores False; gold assumed to always succeed | never | needs a parsed AST and a `kmap`; not reusable as a bare two-result comparator |

| d | Spider 2.0 `compare_pandas_table`\@cafb8673[^d] | per-column **existence** check, not per-row: every gold column (or the declared `condition_cols` subset) must find *some* predicted column, any position, whose value vector matches | `ignore_order` is a per-instance flag (`standard.get(..., False)`, default **False**, i.e. positional); Mini-Dev carries no such flag, so this reading maps it from the gold's own ORDER BY the same way the other readings do | Python, `pandas` column vectors (`DataFrame.values.transpose()`) | extra predicted columns tolerated (nothing requires every predicted column to be used); missing ones fail; **row count must match exactly** for any column pairing to be checked at all | `math.isclose(abs_tol=1e-2)` for any two numeric-typed cells, both int and Decimal-derived | `pd.isna` normalized **to `0`**, so NULL and a real 0 are indistinguishable | numeric types compared loosely via `isclose`; non-numeric via `==` | not modeled in this file; the driver scores any execution failure 0 | never | built for single-CSV-vs-CSV grading with a declared subset of columns to check; assumes row alignment is already correct, which BIRD's server-ordered R-SET rows are not |
| e | BIRD-CRITIC-1 `ex_base`\@f408d6c9[^e] | set (same `calculate_ex` shape as a1) | never inside `ex_base` itself | Python, PostgreSQL, `preprocess_results` runs first | position only, like a1 | Python `==` | untreated beyond date coercion | dates/datetimes to `"YYYY-MM-DD"` strings on both sides first, then Python `==`/hash | any execution or timeout error on either side scores 0; **either side empty also scores 0** (a1 would call two empty results equal) | not applied inside `ex_base`; `remove_distinct` exists but is only invoked by a benchmark-authored `test_case` snippet | each BIRD-CRITIC instance supplies its own `test_cases` (exec'd Python calling `ex_base`, `remove_distinct`, or a QEP-cost comparison); there is no one fixed comparator, `ex_base` is the shared primitive |
| f | LiveSQLBench `ex_base`\@e15cd221[^f] (its own, not e's) | order-sensitive path is **list equality** (order and multiplicity both matter); the default path is **set** (multiplicity dropped, like a1) | order-sensitive only when the caller passes `conditions={"order": True}` (per-instance benchmark metadata; this reading maps it from the gold's own ORDER BY) | Python, PostgreSQL | position only | Decimal/float **rounded to 2 dp, `ROUND_HALF_UP`**, both sides, before comparing | untreated beyond date coercion | dates to strings; decimals/floats rounded (see Float); unhashable cells (dict/list) JSON-dumped to a string first | any execution/timeout error on either side scores 0; **either side empty also scores 0**, same guard as e (line 275 of `test_utils.py`) | same shared-primitive-plus-`test_case` architecture as e | a `ROUND` in the SQL text can also be stripped by a separate helper (`remove_round`), not part of `ex_base` |
| g | defog-ai/sql-eval `compare_df`/`normalize_table`\@b8333241[^g] | set after an **unconditional `drop_duplicates()`** on both sides (stronger than any of the above: every result is deduplicated regardless of the query's own DISTINCT) | rows sorted left-to-right unless the query category is `order_by` or the question text matches the regex `order`, `sort` or `arrange` (word boundary, case-insensitive) | Python, `pandas`, first tries a raw positional `.values ==`, then falls back to the normalized/sorted comparison | columns matched **by name**, sorted alphabetically on both sides; a differently-ordered projection is fine, a renamed one is not (falls to shape mismatch) | plain `==` after `fillna`, no numeric tolerance | **filled with a `-99999` sentinel** before comparing; collides with a real `-99999` value if one exists | `assert_series_equal(check_dtype=False)` in the companion `subset_df`; `compare_df` itself relies on pandas' own loose `==` after `fillna`, which coerces across numeric dtypes | not modeled here; a read failure upstream is the caller's problem | **always effectively added** (`drop_duplicates()` on both sides, unconditionally) | the companion `subset_df` (not run here) checks column-by-column subset membership via sorted-series equality, matching one predicted column to each gold column by content when names differ |
